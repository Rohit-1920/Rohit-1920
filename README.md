### Project 1 · Containerized Web App on Amazon EKS Fargate with GitHub Actions CI/CD

Push-to-deploy pipeline with parallel image builds, ECR push, manifest apply and rollout verification on EKS Fargate.

```mermaid
%%{init: {'theme':'base','themeVariables':{'fontFamily':'Inter, ui-sans-serif, system-ui, sans-serif','primaryColor':'#F1F5F9','primaryBorderColor':'#334155','primaryTextColor':'#0F172A','lineColor':'#475569'}}}%%
flowchart LR
  GA["GitHub Actions<br/>parallel builds"] --> ECR[("Amazon ECR")] --> EKS["EKS on Fargate<br/>multiple replicas"] --> ALB["Multi-AZ ALB<br/>path-based routing"]
  EKS --> RDS[("Private RDS<br/>MariaDB")]
  EKS --> NAT["Shared<br/>NAT Gateway"]
```

**Results:** ~80% less manual deployment effort · ~50% lower networking cost on selected non-prod traffic

- **Network:** VPC prepared for Fargate, with a NAT Gateway and a private pod subnet
- **Database:** private RDS MariaDB with a security group scoped to the VPC CIDR
- **Access:** AWS Load Balancer Controller using an IRSA role limited to one service account
- **Routing:** frontend and API served behind one ALB with path-based routing

### Project 2 · Production GitOps on EKS Fargate with CloudFront and Keyless CI/CD

Production delivery with no long-lived AWS credentials, and a cluster that corrects its own configuration drift.

```mermaid
%%{init: {'theme':'base','themeVariables':{'fontFamily':'Inter, ui-sans-serif, system-ui, sans-serif','primaryColor':'#F1F5F9','primaryBorderColor':'#334155','primaryTextColor':'#0F172A','lineColor':'#475569'}}}%%
flowchart LR
  GA["GitHub Actions<br/>OIDC"] --> ECR[("Amazon ECR")] --> ARGO["Argo CD<br/>sync, prune, self-heal"] --> EKS["EKS on Fargate"]
  GA --> S3[("Private S3")]
  EKS -- IRSA --> BR["Amazon Bedrock"]
  CF["CloudFront<br/>HTTPS only"] -- OAC --> S3
  CF --> ALB["ALB"] --> EKS
  CT["CloudTrail"] -.-> GA
```

**Results:** 100% of long-lived AWS credentials eliminated · ~85% less manual release effort · ~30% lower compute spend through sizing and edge caching

- **Trust:** policy restricted to one repository and one branch
- **Delivery:** static build synced to private S3 and served through CloudFront with OAC
- **Origin:** ALB as the API origin, with HTTPS-only access
- **AI access:** least-privilege Bedrock policy for the backend pod via IRSA

### Project 3 · Microservices Migration from Docker Compose to Kubernetes on Amazon EKS

Three Spring Boot microservices and a React/Vite frontend moved from a single EC2 host to EKS.

```mermaid
%%{init: {'theme':'base','themeVariables':{'fontFamily':'Inter, ui-sans-serif, system-ui, sans-serif','primaryColor':'#F1F5F9','primaryBorderColor':'#334155','primaryTextColor':'#0F172A','lineColor':'#475569'}}}%%
flowchart LR
  DC["Docker Compose<br/>single EC2 host"] --> SV["Containerized<br/>services"] --> ECR[("Amazon ECR")] --> EKS["EKS<br/>manifests, HPA"] --> ALB["ALB Ingress"] --> R53["Route 53<br/>Certbot SSL"] --> PROD(["Production"])
```

**Results:** ~70% less environment setup effort

- **Manifests:** Namespace, ConfigMap, Deployment, Service, ALB Ingress and HPA
- **Cluster:** created with eksctl, Load Balancer Controller configured with IRSA
- **Egress:** NAT Gateway for a stable egress IP
- **Bootstrap:** idempotent script that seeds organizations and users
